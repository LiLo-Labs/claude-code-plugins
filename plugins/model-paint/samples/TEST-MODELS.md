# Test models

These are the models the plugin was actually developed and measured against. The
shipped `creature.stl` fixture is generated by `tests/make_fixture.py` and is **too
easy** — its horns are cones stuck on a sphere, so they have crease boundaries the
cheapest signal finds. It hid a real failure once already. Never treat passing on
it as evidence that a method works; check on the shell.

## Attribution and licensing

`baby-dragon*` is **Generic Baby Dragon by the Bearded Printer**, credited in the
3MF's own metadata ("designed by the talented Bearded Printer"). It is an
articulated flexi print. `scallop-shell-barricade.stl` is a commercial terrain
piece. Neither was created by this project.

They are included here at the repository owner's direction so the test set is
self-contained for any agent picking the work up. If you are not the owner, treat
them as the property of their creators: they are here to reproduce measurements,
not to be redistributed further. If a creator objects, remove them and fall back to
the table below, which is enough to identify what to obtain.

## What each one is for

**`baby-dragon.stl`** — the easy real case. 29 separate connected bodies (it is a
flexi chain, so each link is its own body) and sharp creases around the eyes.
Connected-component splitting alone gets a long way here, which is exactly why it
is not sufficient evidence on its own.

**`scallop-shell-barricade.stl`** — the hard case, and the one that matters. **One
single connected body**, entirely sculpted, nothing crease-bounded. Crease
segmentation put 625,884 of its 626,766 triangles into a single region and returned
59 slivers of 13 to 30 faces. Any new method must be checked against this model.

**`baby-dragon-repaired.stl`** — the same dragon after a third-party repair step,
kept deliberately as a counter-example. It is **not the same geometry**: 475,556
faces against 475,270, 28 components against 29, and a 153x153 footprint against
108x187 because the build item carries a 45 degree rotation. Paint is stored per
triangle index, so a plan built against one file is meaningless against the other.
`scripts/verify.py` exists because of this pair and reports exactly what diverged.

**`baby-dragon-painted-v3.3mf`** — a genuine OrcaSlicer 2.6.32 project, painted in
four colours by hand. This is the ground truth for the file format, and it
confirmed the paint codec was already correct before any real file existed: `4` →
filament 1 (1,218 triangles), `8` → filament 2 (61,458), `1C` → filament 4
(177,882). It also carries the user's real printer profile — Flashforge Creator 5
Pro, four independent 0.4mm nozzles — and 672 keys of project settings, which is
why `paintlib/orca.py` patches that file rather than synthesising one. See
`docs/orca-format.md`.

## Reference measurements

Numbers a later run can check itself against:

- Reading `baby-dragon-painted-v3.3mf` yields one mesh object in
  `3D/Objects/Generic Baby Dragon.stl_1.model`, 475,556 triangles, filament
  histogram `{0: 234998, 1: 1218, 2: 61458, 4: 177882}` where 0 means unpainted and
  prints in the object's own filament (3).
- Repainting 2,000 of its triangles and writing it back leaves geometry and
  placement identical, all 473,556 other triangles unchanged, and all 27 archive
  entries preserved.
- Surface over-segmentation of the shell at `target_patches=2500` gives 2,500
  patches, median 240 faces, largest 0.07% of area, zero single-face patches, in
  about 65 seconds.
- One click on a barnacle colony (`patch_select.py --grow local --tolerance 0.30`,
  `--at iso:562,247` against a session built by `inspect_model.py`) selects 49
  patches, 2.08% of surface area, stopping at the rib.
- The open problem: 13 features clicked at that fixed tolerance give 9 sensible
  selections, 2 runaways (28.06% and 8.48% of the model) and 1 collapse to 259
  triangles. See `HANDOFF.md`.
